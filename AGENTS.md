# WaterDrop Project Instructions

These instructions apply to all work under this repository.

- Before committing or pushing project work, update the progress-like Markdown files that reflect the changed state of the project. Today that means `progress.md`, `handover.md`, and `docs/assessment.md`; also include any future Markdown tracker, handover, assessment, status, progress, changelog, or roadmap file that clearly serves the same purpose.
- Follow this documentation update rule even in a new conversation. Inspect the existing progress-like files first so the update continues the project history instead of starting a duplicate tracker.
- After every Codex-made local project change, commit intentionally and push the current branch to GitHub before ending the turn, even in a new conversation. If the user explicitly says not to push, follow the user's latest instruction for that turn.
- When the user asks to check local changes and push to GitHub, inspect the working tree, review the diff, run checks appropriate to the changed files, commit intentionally, and push the current branch.
- Never commit local environment files, secrets, Vercel project metadata, build output, screenshots, or local agent artifacts unless the user explicitly asks for that exact artifact.
